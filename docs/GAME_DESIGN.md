# 사이보그 파츠 로그라이크 — 핵심 기획

## 1. 게임의 정체성

사이보그 신체에 파츠를 장착해 자신만의 무기를 만드는 모바일 액션 로그라이크.

전투에서 파츠를 얻고, 전투 사이에 조립을 변경하며 다음 층으로 진행한다.
핵심은 높은 공격력의 완성 무기를 얻는 것보다, 기능을 조합하고 발동 조건을 바꿔 강력한 시너지를 발견하는 재미다.

블록 코딩처럼 배치하고 연결하지만 복잡한 문법이나 조건식을 직접 작성하지 않는다.
개별 파츠는 쉽게 이해되고, 조합 결과에서 깊이가 생겨야 한다.
특정 완성 능력 하나만을 위한 기능보다 여러 조합에 재사용 가능한 기능을 우선한다.

이 문서의 예시는 의도를 설명하기 위한 것이다. 수치와 이름을 모두 최종 확정 사항으로 취급하지 않는다.

## 2. 한 판의 흐름

시작 무기 지급
→ 전투
→ 파츠·재화 획득
→ 정비와 조합 변경
→ 다음 층 유형 선택
→ 더 어려운 전투와 성장 반복

층을 올라갈 때 다음 전투 유형을 선택할 수 있게 한다.

중심 전투 유형:
- 방 탐험형: 여러 방을 이동하며 전투.
- 웨이브형: 한 공간에서 연속으로 등장하는 적과 전투.

상점, 회복, 조건 변환기, 랜덤 추출기, 이벤트 등으로 성장 기회를 제공한다.
최종 목표, 층수, 사망 후 유지되는 성장 범위는 미정이다.

정비는 전투 종료 후 버튼이나 단축키로 연다.
전투 중에는 파츠를 변경할 수 없다.
정비 전용 방은 필요하지 않다.

## 3. 조작과 장착 구조

모바일 조작:
- 이동 패드 1개.
- 무기 패드 2개.
- 이동은 공격 파츠와 별개다.

운용 능력:
- 수동 능력 2개.
- 자동 능력 2개.
- 총 4개의 능력.

수동 공격은 당겨서 조준하고 놓으면 발사하는 것이 기본이다.
차징 파츠를 장착하면 충전이 가능하다.
쿨타임이 일정 기준 이하가 되면 토글형으로 바꾸는 방향이다.
자동 입력의 구체적인 조건과 토글 세부 조작은 미정이다.

장착 화면은 사이보그 신체를 중심으로 구성한다.
전체 신체 화면에서 팔 등의 부위를 선택하면 해당 부위의 상세 장착 화면으로 이동한다.
부위마다 여러 파츠를 넣을 수 있고 슬롯 수가 다를 수 있다.

베이스는 단순한 장착 틀과 과부하 한도를 제공한다.
실제 능력은 파츠가 결정한다.
부위 목록·슬롯 수·수동/자동 능력과의 대응은 아직 확정하지 않았다.

## 4. 파츠의 역할

### 기본 파츠
공격의 기본 형태를 결정한다.

초기 후보 3개:
- 투사체
- 휘두르기
- 빔

### 효과 파츠
공격에 새로운 기능이나 행동을 추가한다.

초기 후보 6개:
- 폭발
- 화상
- 끌어오기
- 돌진
- 터렛
- 분열

터렛은 기본 공격이 아니라 기본 공격을 대신 사용하는 효과다.
예: 투사체 + 저격 + 터렛 = 저격탄을 발사하는 터렛.

모든 파츠를 모든 형태와 무조건 호환할 필요는 없다.

### 보조 파츠
공격 성격 또는 다른 파츠의 작동을 변경한다.

상시형:
장착하면 계속 적용된다.
예: 저격, 산탄, 속사, 거대화, 장거리, 차징.

조건형:
특정 상황에서 이득이 발생한다.
예: 화상 피해 시 쿨타임 감소, 이동 중 쿨타임 회복 가속, 처치 시 쿨타임 감소.

연결형:
배치에 따라 다른 파츠에 영향을 준다.
핵심 예시:
- 왼쪽 파츠 효과 2배.
- 오른쪽 파츠 비활성화 대신 나머지 파츠 효과 1.5배.
- 오른쪽 파츠 사용 시 왼쪽 파츠 쿨타임 감소.
- 왼쪽 효과 발동 시 오른쪽 파츠를 원래 조건과 관계없이 즉시 발동.

무슨 파츠를 넣는지뿐 아니라 어디에 놓는지도 중요하다.
상시형·조건형·연결형은 이해를 위한 분류이며 별도 슬롯을 반드시 추가하라는 뜻은 아니다.

## 5. 익숙한 무기를 조립의 출발점으로 제공

저격·산탄·속사 파츠에는 관련 수치와 연출을 묶는다.
유저가 개별 수치 파츠를 여러 개 조립해야 저격총이 되는 구조는 피한다.

예:
- 저격: 피해·탄속 증가, 쿨타임 증가, 외형과 발사음 변화.
- 산탄: 발사 수와 퍼짐 증가, 개별 피해 감소.
- 속사: 쿨타임 감소, 개별 피해 감소.

시작 무기도 실제 파츠 조합으로 지급한다.
- 저격총 = 투사체 + 저격.
- 샷건 = 투사체 + 산탄.
- 기관총 = 투사체 + 속사.

시작 파츠를 빼거나 바꾸고 다른 곳에 사용할 수 있어야 한다.
플레이어는 익숙한 무기를 쓰다가 구성 파츠를 발견하며 조립을 배운다.

## 6. 핵심 특색: 발동 조건 변환

파츠는 조건과 기능이 묶인 형태로 제공한다.
변환기를 사용하면 기능은 유지하면서 발동 조건을 바꿀 수 있다.

예:
적중 시 분열 → 사용 시 분열.

맞은 뒤 갈라지던 탄환이 발사 순간 갈라지는 공격으로 바뀐다.

변환 규칙:
- 해당 기능에서 작동 가능한 다른 조건 중 랜덤 선택.
- 현재 조건은 제외.
- 대체 조건이 하나면 그 조건으로 확정 변환.
- 대체 조건이 없으면 변환 불가.

플레이어가 조건문을 직접 작성하는 방식은 아니다.
조건 변환으로 같은 기능의 새로운 활용법을 발견하는 것이 목적이다.

쉬운 조건이 항상 우월해지는 문제와 과도한 반복 발동은 전투에서 검증해야 한다.
발동 예산이나 내부 쿨타임 같은 해결책은 아직 확정하지 않았다.

## 7. 수치·소파츠·키워드·과부하

각 파츠는 피해·범위·사거리·쿨타임 등 필요한 기본 수치를 갖는다.
수치를 직접 입력하는 것보다 소파츠로 개조하는 방향을 우선한다.

소파츠 예:
- 쿨타임 증가 대신 피해 증가.
- 적 처치 시 남은 쿨타임 감소.

투사체·폭발·화상·설치물 같은 키워드로 관련 효과를 강화할 수 있다.

파츠와 소파츠는 과부하 비용을 가진다.
장착 비용 합계가 한도를 초과하면 장착할 수 없다.
강한 기능에 집중할지, 다양한 기능을 연결할지 선택하게 한다.

부위별/전체 과부하, 소파츠 슬롯 수, 비용 산식은 미정이다.

## 8. 희귀도와 수집

희귀도에는 두 가지가 반영된다.
1. 같은 기능 내의 성능 차이.
2. 기능 자체의 특별함과 강력함.

예:
- 공격력 증가량이 높으면 높은 등급.
- 산탄 4발보다 6발이 높은 등급.
- 왼쪽 효과 2배는 전설급.
- 오른쪽 사용 시 왼쪽 쿨타임 감소는 상황을 타므로 희귀급.

모든 파츠가 모든 등급에 존재할 필요는 없다.
특정 기능은 높은 등급부터 등장할 수 있다.

성장 방식:
- 같은 파츠를 모아 상위 등급으로 강화.
- 안 쓰는 다른 파츠들을 소비해 랜덤 추출.
- 조건이 아쉬운 파츠는 변환기로 변경.

필요 개수·확률·영구 수집 여부는 미정이다.

캐릭터 전체에 영향을 주는 능력은 무기 파츠와 구분한다.
예: 받는 피해 2배 대신 모든 무기 피해 2배.
신체에 장착한다고 모든 파츠가 전역 효과가 되는 것은 아니다.

## 9. 레시피 합성 — 후순위

일반 장착은 기능을 함께 적용한다.
레시피 합성은 재료를 결합해 기능과 연출이 통합된 새 파츠를 만든다.

예:
- 휘두르기 + 빔 → 광선검.
- 휘두르기 + 투사체 → 검기.
- 특정 파츠 세트 → 강력한 고유 파츠.

단순히 두 효과를 연달아 사용하는 결과와 구별한다.
같이 장착했다고 자동 합성되지 않고, 합성기에서 직접 선택한다.
재료 계승·소모·분해 규칙은 미정이다.

기본 전투, 조립, 조건 변환 검증 이후에 개발한다.

## 10. 아트와 인터페이스

플레이 캐릭터:
- 도트 스타일.
- 머리가 큰 귀여운 SD 비율.
- 사이보그 개조 콘셉트.

장착 화면:
- 특정 캐릭터 대신 중립적 홀로그램 신체.
- 하늘색·청록빛과 짙은 파란 배경.
- 미래적인 반투명 패널과 얇은 선.
- 신체 부위 선택 → 상세 장착 화면.
- 배경 아트와 실제 슬롯·파츠·텍스트는 분리.

과한 보라·분홍 네온과 단일 무기 중심의 초기 디자인은 채택하지 않는다.
대화 시안 이미지가 저장소에 있다고 가정하지 않는다.

## 11. 개발 우선순위와 검증

먼저 조립한 무기가 실제로 다르게 작동하는 최소 전투를 만든다.

1. 이동·조준·발사·적·피해·전투 종료.
2. 투사체와 저격/산탄/속사, 과부하, 전투 후 정비.
3. 폭발·분열과 발동 조건 변환.
4. 신체 부위 장착, 연결형 파츠, 수동/자동 능력 확장.
5. 층 진행·보상·상점·희귀도·강화·추출.
6. 나머지 콘텐츠.
7. 고유 레시피와 세트 합성.

첫 검증 목표:
- 파츠 교체가 공격 동작과 연출을 확실히 바꾸는가.
- 조립 결과를 쉽게 이해할 수 있는가.
- 조건 변환으로 다른 플레이가 생기는가.
- 모바일 조작과 전투 후 정비가 편한가.
- UI 설명과 실제 전투 결과가 일치하는가.
- 연결과 반복으로 무한 재귀가 발생하지 않는가.

## 12. 개발 전에 확인할 큰 결정

- 현재 저장소 코드와 기존 변경 사항.
- 사용할 엔진과 타깃 플랫폼.
- 신체 부위와 능력 4개의 대응.
- 쿨타임과 과부하의 적용 단위.
- 한 판 성장과 영구 성장의 구분.
- 한 판의 승리·패배 조건과 전체 길이.

엔진은 아직 결정하지 않았다.
세부 파츠 수치보다 전체 플레이 흐름과 핵심 조합 경험을 먼저 검증한다.
미정 항목을 임의로 확정하지 말고, 중요한 구조 결정과 되돌리기 쉬운 임시 수치를 구분한다.
