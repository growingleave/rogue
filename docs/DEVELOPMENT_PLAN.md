# 개발 착수 계획

기획 기준: `GAME_DESIGN.md`. 이 문서는 구현 순서와 검증 계획이며, 미정 기획을 확정하지 않는다.

## 현재 저장소 확인

- 작업 전 미커밋 변경 사항 없음. 게임 코드, 엔진 설정, 빌드 및 테스트 구성 없음.
- 기존 파일은 `.gitattributes`, `docs/GAME_DESIGN.md`의 빈 작성 틀이었으며, 원격 `main`에는 `HELLO.txt`가 추가되어 있었다.
- 작업 브랜치 `work`를 원격 `main`의 `a903bf4`까지 fast-forward하여 기존 커밋과 파일을 보존했다.
- 빈 기획서 틀에 제공된 기획 전문을 저장하고, 루트에 Claude 작업 안내를 추가한다.

## 착수 전 결정

1. 엔진은 웹(TypeScript + Vite, Canvas 2D)으로 결정했다. 앱 포장 등 배포 형태는 미정이다.
2. 첫 검증용 전투의 시작·종료 기준을 합의한다. 자동 공격은 우선 가장 가까운 적을 노린다. 한 판 전체의 길이나 최종 승패 규칙과 구분한다.
3. 판 배치 단계를 마무리하기 전에 쿨타임 적용 단위와 와이어 최대 길이를 확정한다. 공격 형태가 없으면 기본 투사체를 쏜다. 와이어끼리는 칸을 나눠 쓰지 않는다. 과부하·소파츠 유지 여부와 판·신체 부위 관계는 해당 확장 단계 전에 결정한다.
4. 영구 성장, 층수, 추출 확률, 판 확장 가격, 합성 규칙은 관련 단계까지 미정으로 유지한다.

## 단계별 작업과 통과 기준

| 단계 | 구현 범위 | 검증 기준 |
| --- | --- | --- |
| 1. 최소 전투 | 결정된 엔진으로 이동·자동 공격·적·피해·전투 종료 구현 | 이동 입력만으로 전투가 가능하고 자동 공격·피해·종료가 일관되게 처리됨 |
| 2. 판 배치와 정비 | 4x4 판, 입력 파츠와 와이어 긋기, 투사체·저격·산탄·속사, 자동 연계, 시작 무기 배치, 전투 후 정비 | 배치 변경으로 동작·연출이 구별되고 와이어 표시와 결과가 일치함. 와이어 규칙(상하좌우·겹침 금지·최대 길이)이 지켜짐. 전투 중 판 변경 불가 |
| 3. 입력·효과 확장 | 이동할 때 입력, 폭발·분열·관통·유도·레이저, 강화·가속 | 각 파츠가 설명대로 작동하고 서로 합쳐질 때 결과를 이해할 수 있음 |
| 4. 판 확장 | 테트리스 모양 파츠, 특수 파츠, 특수 조합, 코인 판 확장 | 모양 배치와 특수 파츠의 영향 범위를 이해할 수 있고, 연쇄에서 임시 상한이 작동해 무한 재귀가 발생하지 않음 |
| 5. 한 판 성장 | 층 선택·보상·상점·희귀도·강화·추출 | 합의된 성장 범위와 진행 규칙이 작동하고 배치 선택 기회가 생김 |
| 6. 콘텐츠 확장 | 나머지 파츠와 입력 조건, 전투 유형과 이벤트 | 각 기능의 호환성과 모바일 판 가독성·정비 사용성을 재검증 |
| 7. 레시피 합성 | 합의된 재료·계승·소모·분해 규칙과 고유 파츠 | 자동 연계·특수 조합과 명확히 다른 통합 기능·연출을 제공 |

각 단계는 작은 변경 단위로 구현하고 검증 결과를 남긴 뒤 다음 단계로 진행한다. 임시 피해·쿨타임·판 크기 등은 교체 가능한 데이터로 관리하는 방향을 검토하되, 엔진별 구현 구조는 아직 정하지 않는다.

## 핵심 실험과 미해결 위험

- 같은 전투 조건에서 저격·산탄·속사 배치 교체 전후의 행동과 연출, 이해도를 비교한다.
- 같은 파츠라도 와이어 순서와 위치를 바꾸면 플레이가 달라지는지 확인한다.
- 자동 연계에서 어울리지 않는 효과 조합을 모아 특수 조합 후보 목록을 만든다. 레이저 + 관통(효과 없음), 레이저 + 유도(구부러짐), 레이저 + 분열(갈래)은 정해졌다.
- 연쇄를 만드는 파츠가 다시 생기면 고리 시나리오를 정리하고 `GAME_DESIGN.md` 8장의 임시 상한을 적용한다.
- 실제 모바일 기기에서 이동만 하는 조작, 손가락으로 와이어 긋기, 판 화면의 칸 크기와 가독성, 전투 후 정비의 편의성을 검증한다.

## 현재 초안: 허수아비 테스트

1단계와 2단계 일부를 허수아비 상대로 확인하는 초안이다. 적의 공격, 전투 종료, 정비 화면 전환은 아직 없다.

- 이동: 키보드 WASD·방향키, 화면을 누르고 끄는 가상 조이스틱.
- 4x4 판, 모든 파츠 1x1, 회전 없음. 판의 칸을 눌러 파츠를 놓고 지우개로 뺀다.
- 와이어는 판 위쪽의 배선 버튼으로 그린다. 누르면 배선 모드가 되고 버튼이 배선 완료로 바뀐다. 배선 완료를 누르면 끝난다.
- 배선 모드: 입력 파츠를 누른 뒤 이을 수 있는 칸(점선으로 빛남)을 차례로 누른다. 마지막 칸을 다시 누르면 한 칸 줄고, 입력 파츠를 다시 누르면 와이어가 지워진다. 입력 파츠에서 끌어서 새로 그릴 수도 있다.
- 놓인 파츠를 누르면 수치가 보이고, 칸 모서리의 ✕로 지운다. 모든 파츠는 끌거나, 누른 뒤 빈 칸을 눌러 옮긴다. 입력 파츠를 옮기면 와이어는 새로 그린다.
- 판 위쪽 도구: 준비된 배치 불러오기, 배선, 비우기.
- 입력 파츠 2종(타이머·이동할 때), 효과 파츠 10종(저격·산탄·속사·거대화·폭발·분열·화상·관통·유도·레이저), 강화 파츠 2종(강화·가속).
- 와이어는 파츠 아래에 선으로 그리고, 발동할 때 와이어를 따라 칸이 차례로 깜빡인다.
- 가장 가까운 허수아비를 자동으로 노리고, 화면 왼쪽 위에 최근 5초 DPS와 투사체 수를 표시한다.
- 테스트 편의를 위해 전투 중에도 판을 바꿀 수 있다. 실제 게임에서는 전투 중 변경이 불가다.
- 판 계산(와이어 규칙·자동 연계·강화·가속·쿨타임·파츠 옮기기·수치 설명)은 `src/board.test.ts`, 레이저 경로(구부러짐·갈래)는 `src/laser.test.ts`로 검증한다.

### 초안 파츠 수치 (모두 임시값)

수치의 원본은 코드(`src/parts.ts`, `src/tuning.ts`)이며, 게임 안에서 파츠를 누르면 같은 수치가 보인다.

| 파츠 | 종류 | 수치 |
| --- | --- | --- |
| 타이머 | 입력 | 기본 피해 10, 쿨타임 1초 |
| 이동할 때 | 입력 | 기본 피해 8, 쿨타임 0.5초 → 0.5초 × 이동속도 220 = 110px 움직일 때마다 |
| 저격 | 효과 | 피해 ×2.2, 탄속·레이저 길이 ×1.6, 쿨타임 ×1.5 |
| 산탄 | 효과 | 탄 수 +2, 피해 ×0.6 |
| 속사 | 효과 | 쿨타임 ×0.55, 피해 ×0.8 |
| 거대화 | 효과 | 탄 크기 ×1.8, 피해 ×1.3, 탄속 ×0.85 |
| 폭발 | 효과 | 폭발 반경 55px, 폭발 피해 = 공격 피해의 50% |
| 분열 | 효과 | 투사체: 작은 탄 3개(피해 50%). 레이저: 3갈래(길이·피해 50%) |
| 화상 | 효과 | 초당 6 피해, 2초 |
| 관통 | 효과 | 적 2명 더 관통 (레이저에는 효과 없음) |
| 유도 | 효과 | 유도 세기 5 (초당 회전 각도, 라디안) |
| 레이저 | 효과 | 피해 ×0.8, 0.35초 동안 5번 연타, 1번에 공격 피해의 30% |
| 강화 | 강화 | 붙은 파츠의 공격 피해 +30% |
| 가속 | 강화 | 붙은 입력 파츠 쿨타임 ×0.75 |

공통: 기본 탄속 420, 탄 크기 5, 이동속도 220, 와이어 최대 5칸, 화면 위 투사체 최대 200개.
