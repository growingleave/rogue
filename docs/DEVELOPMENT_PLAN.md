# 개발 착수 계획

기획 기준: `GAME_DESIGN.md`. 이 문서는 구현 순서와 검증 계획이며, 미정 기획을 확정하지 않는다.

## 현재 저장소 확인

- 작업 전 미커밋 변경 사항 없음. 게임 코드, 엔진 설정, 빌드 및 테스트 구성 없음.
- 기존 파일은 `.gitattributes`, `docs/GAME_DESIGN.md`의 빈 작성 틀이었으며, 원격 `main`에는 `HELLO.txt`가 추가되어 있었다.
- 작업 브랜치 `work`를 원격 `main`의 `a903bf4`까지 fast-forward하여 기존 커밋과 파일을 보존했다.
- 빈 기획서 틀에 제공된 기획 전문을 저장하고, 루트에 Claude 작업 안내를 추가한다.

## 착수 전 결정

1. 사용자의 개발 경험과 Claude 개발 환경, 모바일 실기기 검증 및 배포 요구를 확인해 엔진과 구체적인 타깃 플랫폼을 결정한다. 현재 엔진은 선택하지 않는다.
2. 첫 검증용 전투의 시작·종료 기준과 자동 공격의 조준 규칙을 합의한다. 한 판 전체의 길이나 최종 승패 규칙과 구분한다.
3. 판 배치 단계 진입 전에 쿨타임 적용 단위, 화살표 범위에 공격 형태가 없을 때와 여러 출력 파츠가 겹칠 때의 처리를 결정한다. 과부하·소파츠 유지 여부와 판·신체 부위 관계는 해당 확장 단계 전에 결정한다.
4. 영구 성장, 층수, 추출 확률, 판 확장 가격, 합성 규칙은 관련 단계까지 미정으로 유지한다.

## 단계별 작업과 통과 기준

| 단계 | 구현 범위 | 검증 기준 |
| --- | --- | --- |
| 1. 최소 전투 | 결정된 엔진으로 이동·자동 공격·적·피해·전투 종료 구현 | 이동 입력만으로 전투가 가능하고 자동 공격·피해·종료가 일관되게 처리됨 |
| 2. 판 배치와 정비 | 4x4 판, 출력 파츠와 화살표 표시, 투사체·저격·산탄·속사, 자동 연계, 시작 무기 배치, 전투 후 정비 | 배치 변경으로 동작·연출이 구별되고 화살표 표시와 결과가 일치함. 전투 중 판 변경 불가 |
| 3. 방향 변환 | 폭발·분열, 강화 파츠, 방향 변환기와 미리보기·취소 | 변환이 화살표만 바꾸고 파츠 기능은 보존함. 취소 시 원래 방향 유지. 변환 전후 플레이 차이를 검증 |
| 4. 판 확장 | 테트리스 모양 파츠, 특수 파츠, 특수 조합, 코인 판 확장 | 모양 배치와 특수 파츠의 영향 범위를 이해할 수 있고, 연쇄에서 임시 상한이 작동해 무한 재귀가 발생하지 않음 |
| 5. 한 판 성장 | 층 선택·보상·상점·희귀도·강화·추출 | 합의된 성장 범위와 진행 규칙이 작동하고 배치 선택 기회가 생김 |
| 6. 콘텐츠 확장 | 나머지 파츠, 화살표 종류, 전투 유형과 이벤트 | 각 기능의 호환성과 모바일 판 가독성·정비 사용성을 재검증 |
| 7. 레시피 합성 | 합의된 재료·계승·소모·분해 규칙과 고유 파츠 | 자동 연계·특수 조합과 명확히 다른 통합 기능·연출을 제공 |

각 단계는 작은 변경 단위로 구현하고 검증 결과를 남긴 뒤 다음 단계로 진행한다. 임시 피해·쿨타임·판 크기 등은 교체 가능한 데이터로 관리하는 방향을 검토하되, 엔진별 구현 구조는 아직 정하지 않는다.

## 핵심 실험과 미해결 위험

- 같은 전투 조건에서 저격·산탄·속사 배치 교체 전후의 행동과 연출, 이해도를 비교한다.
- 같은 판에서 방향 변환 전후로 발동되는 파츠와 플레이가 달라지는지 확인한다.
- 자동 연계에서 어울리지 않는 효과 조합을 모아 특수 조합 후보 목록을 만든다.
- 2D 판에서 파츠끼리 서로 발동하는 고리 시나리오를 정리한다. 우선 `GAME_DESIGN.md` 8장의 임시 상한(연쇄 깊이·같은 파츠 발동 횟수·투사체 수)을 적용하고 테스트로 조정한다.
- 실제 모바일 기기에서 이동만 하는 조작, 판 화면의 칸 크기와 화살표 가독성, 전투 후 정비의 편의성을 검증한다.
