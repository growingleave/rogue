# 개발 착수 계획

기획 기준: `GAME_DESIGN.md`. 이 문서는 구현 순서와 검증 계획이며, 미정 기획을 확정하지 않는다.

## 현재 저장소 확인

- 작업 전 미커밋 변경 사항 없음. 게임 코드, 엔진 설정, 빌드 및 테스트 구성 없음.
- 기존 파일은 `.gitattributes`, `docs/GAME_DESIGN.md`의 빈 작성 틀이었으며, 원격 `main`에는 `HELLO.txt`가 추가되어 있었다.
- 작업 브랜치 `work`를 원격 `main`의 `a903bf4`까지 fast-forward하여 기존 커밋과 파일을 보존했다.
- 빈 기획서 틀에 제공된 기획 전문을 저장하고, 루트에 Claude 작업 안내를 추가한다.

## 착수 전 결정

1. 사용자의 개발 경험과 Claude 개발 환경, 모바일 실기기 검증 및 배포 요구를 확인해 엔진과 구체적인 타깃 플랫폼을 결정한다. 현재 엔진은 선택하지 않는다.
2. 첫 검증용 전투의 시작·종료 기준과 최소 입력 범위를 합의한다. 한 판 전체의 길이나 최종 승패 규칙과 구분한다.
3. 조립 단계 진입 전에 쿨타임·과부하 적용 단위를 결정한다. 부위와 능력 대응은 해당 확장 단계 전에 결정한다.
4. 영구 성장, 층수, 추출 확률, 합성 규칙은 관련 단계까지 미정으로 유지한다.

## 단계별 작업과 통과 기준

| 단계 | 구현 범위 | 검증 기준 |
| --- | --- | --- |
| 1. 최소 전투 | 결정된 엔진으로 이동·조준·발사·적·피해·전투 종료 구현 | 모바일 입력으로 조준과 발사가 가능하고 피해 및 종료가 일관되게 처리됨 |
| 2. 조립과 정비 | 투사체, 저격·산탄·속사, 탈착 가능한 시작 무기, 과부하, 전투 후 정비 | 교체로 동작·연출이 구별되고 UI와 결과가 일치함. 전투 중 교체와 한도 초과 장착은 불가 |
| 3. 조건 변환 | 폭발·분열 및 기능별 호환 조건 목록과 랜덤 변환 | 기능을 보존하고 현재 조건을 제외함. 대체 조건 0개·1개·여러 개를 각각 확인하고 플레이 차이를 검증 |
| 4. 장착 확장 | 신체 부위 상세 화면, 연결형 파츠와 파츠 라인, 터치형 1개·자동/조건 2개 구성 검증 후 능력 수 재검토 | 배치 효과와 영향 범위를 이해할 수 있고 반복 연결에서 무한 재귀가 발생하지 않음 |
| 5. 한 판 성장 | 층 선택·보상·상점·희귀도·강화·추출 | 합의된 성장 범위와 진행 규칙이 작동하고 조합 선택 기회가 생김 |
| 6. 콘텐츠 확장 | 나머지 기본·효과·보조 파츠, 전투 유형과 이벤트 | 각 기능의 호환성과 모바일 조작·정비 사용성을 재검증 |
| 7. 레시피 합성 | 합의된 재료·계승·소모·분해 규칙과 고유 파츠 | 일반 동시 장착과 명확히 다른 통합 기능·연출을 제공 |

각 단계는 작은 변경 단위로 구현하고 검증 결과를 남긴 뒤 다음 단계로 진행한다. 임시 피해·쿨타임·비용 등은 교체 가능한 데이터로 관리하는 방향을 검토하되, 엔진별 구현 구조는 아직 정하지 않는다.

## 핵심 실험과 미해결 위험

- 같은 전투 조건에서 저격·산탄·속사 교체 전후의 행동과 연출, 이해도를 비교한다.
- 적중 시 분열과 사용 시 분열을 비교해 조건 변환이 다른 플레이를 만드는지 확인한다.
- 변환의 쉬운 조건이 항상 우월한지, 연결이 과도한 반복 발동을 일으키는지 관찰한다.
- 연결형 구현 전 반복·순환 시나리오를 정리하고 종료를 보장할 정책을 결정한다. 우선 `GAME_DESIGN.md` 7장의 임시 상한(연쇄 깊이·같은 파츠 발동 횟수·투사체 수)을 적용하고 테스트로 조정한다.
- 실제 모바일 기기에서 당겨 조준 후 놓기, 전투 후 정비의 편의성을 검증한다.
